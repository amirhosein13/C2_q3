# برگزاری آزمون وقتی فقط دسترسی پنل ادمین CMS را دارید

فرض: کسی CMS را روی سروری نصب کرده و شما فقط **نام کاربری و رمز صفحه‌ی ادمین** (AdminWebServer) را دارید.
پس به ترمینال سرور دسترسی ندارید و `cmsImportTask` قابل استفاده نیست. همه‌چیز را از طریق صفحه‌ی وب اضافه می‌کنید.

اسم دکمه‌ها و فیلدها از قالب‌های صفحه‌ی ادمین **CMS 1.5.1** برداشته شده‌اند. اگر سرور شما نسخه‌ی دیگری است،
ممکن است کمی فرق کنند. نسخه معمولاً پایین صفحه‌ی ادمین نوشته شده است.

---

## مرحله ۰: چیزهایی که از مدیر سرور بپرسید

1. **سطح دسترسی حساب شما**: باید «all» باشد. با دسترسی «messaging» فقط می‌توانید به پرسش‌ها جواب دهید و نمی‌توانید سوال یا کاربر بسازید.
2. **نسخه‌ی CMS** (ترجیحاً 1.5.x).
3. **آدرس صفحه‌ی شرکت‌کننده‌ها** (ContestWebServer؛ معمولاً پورت 8888 یا یک دامنه).
4. **آیا آزمون از قبل ساخته شده** یا خودتان بسازید.
5. وقتی آزمون را ساختید یا عوض کردید، از مدیر بخواهید **سرویس‌ها را برای آن آزمون ری‌استارت کند**:
   `cmsResourceService -a <ID آزمون>`. صفحه‌ی شرکت‌کننده‌ها فقط آزمونی را نشان می‌دهد که سرویس‌ها با آن اجرا شده‌اند.
6. **محدودیت حجم آپلود**: آیا جلوی صفحه‌ی ادمین nginx هست؟ اگر هست، `client_max_body_size` باید حداقل
   `100m` باشد، وگرنه آپلود zip تست‌ها خطا می‌دهد.
7. چند Worker دارند، تا بدانید داوری هم‌زمان چقدر سریع است.

---

## مرحله ۱: ساخت بسته‌ی آپلود (روی کامپیوتر خودتان)

در ریپو:

```bash
cd C2_q1/lice
tps gen                                              # ساخت تست‌ها (حدود ۱ دقیقه)
python3 ../tools/make_cms_upload.py statement/lice-fa.pdf
```

خروجی در پوشه‌ی `lice/cms-upload/` است:

| فایل | کاربرد |
|---|---|
| `SETTINGS.md` | فهرست همه‌ی فیلدهایی که باید پر کنید، با مقدار درست |
| `statement-fa.pdf` | متن سوال |
| `attachments/lice.zip` | بسته‌ی شرکت‌کننده‌ها (grader نمونه، هدر، قالب کد، مثال) |
| `managers/grader.cpp`، `managers/lice.h` | grader داوری و هدر |
| `managers/checker` | checker **کامپایل‌شده** (فایل اجرایی لینوکس x86-64، static). در این حالت CMS خودش checker را کامپایل نمی‌کند |
| `testcases-part1.zip`، `testcases-part2.zip` | ۷۱ تست، در دو بخش زیر ۱۰۰ مگابایت (سقف پیش‌فرض آپلود) |
| `score_type_parameters.json` | پارامترهای زیرمسئله‌ها، برای کپی‌کردن در پنل |

> اگر سرور CMS معماری غیر از x86-64 دارد (بسیار نادر)، checker باید روی همان معماری کامپایل شود.

## مرحله ۲: ساخت آزمون (اگر ساخته نشده)

1. منوی چپ → **Contests** → ساخت آزمون جدید (**New contest**) → یک **Name** کوتاه، مثلاً `gold-w01`.
2. در صفحه‌ی آزمون:
   - **Description**: عنوان نمایشی.
   - **Allowed languages**: فقط یک گزینه‌ی C++ با g++ را تیک بزنید، مثلاً C++17. grader ما فقط C++ دارد.
   - **Start** و **End**.
   - **Timezone**: `Asia/Tehran`.
   - **Per-user time** فقط اگر هر نفر از لحظه‌ی ورودش مدت مشخصی وقت دارد.
   - **Tokens**: Disabled.
   - Save.
3. **ID آزمون** را از آدرس صفحه بردارید (مثلاً `.../contest/3` یعنی ۳) و برای ری‌استارت سرویس‌ها به مدیر سرور بدهید.

## مرحله ۳: ساخت سوال

### ۳.۱ ساخت
منوی چپ → **Tasks** → سوال جدید (**New task**) → **Name** = `lice` → ساخت.

CMS خودش Submission format را `lice.%l` می‌گذارد و یک dataset پیش‌فرض می‌سازد. آن dataset را در ۳.۳ درست می‌کنیم.

### ۳.۲ بخش بالای صفحه‌ی سوال
مطابق `SETTINGS.md`:

- **Title**: `پرش شپش`
- **Statements** → افزودن (Add statement) → Language code: `fa` → فایل `statement-fa.pdf` → بعد تیک **Primary?** کنار `fa`.
- **Attachments** → افزودن → `attachments/lice.zip`.
- **Submission format**: `lice.%l` (باید خودکار پر شده باشد).
- **Feedback level**: `Full`: شرکت‌کننده نتیجه‌ی تست‌ها را می‌بیند. `Restricted`: کمتر می‌بیند.
- **Tokens**: Disabled.
- **Maximum number of submissions**: مثلاً `50`. **Minimum interval between submissions**: مثلاً `60` (ثانیه).
- **Score precision**: `2`.
- **Score mode**: گزینه‌ی آخر را انتخاب کنید:
  «Use the sum over each subtask of the best result for that subtask across all submissions (IOI 2017-)».
  **این مهم است**؛ پیش‌فرض CMS چیز دیگری است.

### ۳.۳ بخش dataset (پایین همان صفحه)
- **Time limit**: `2` ثانیه. **Memory limit**: `256` MiB.
- **Task type**: `Batch`
  - Compilation: **Submissions are compiled with a grader**
  - I/O: هر دو جعبه‌ی Input file و Output file **خالی** بمانند (یعنی stdin/stdout).
  - Output evaluation: **Outputs are compared by a comparator**
- **Managers** → افزودن (Add manager)، سه بار: `checker`، `grader.cpp`، `lice.h`.
  اسم‌ها باید **دقیقاً** همین باشند. CMS دنبال فایلی به اسم `checker` و `grader.cpp` می‌گردد.
- **Score type**: `GroupMin`
- **Score type parameters**: کل محتوای `score_type_parameters.json` را کپی و در جعبه paste کنید.
  این یک لیست JSON با ۶ ردیف است (۰، ۱۰، ۱۲، ۱۸، ۲۵، ۳۵). هر ردیف یک regex دارد که تست‌های آن زیرمسئله را مشخص می‌کند.
- **Save** (دکمه‌ی پایین صفحه).

### ۳.۴ تست‌ها
در بخش testcases → **Add multiple testcases**:
- Archive: `testcases-part1.zip`
- Public: تیک نزنید. فقط اگر می‌خواهید جزئیات هر تست برای شرکت‌کننده نمایش داده شود، تیک بزنید.
- Input file names template: `*.in`
- Output file names template: `*.out`
- Upload

همین کار را برای `testcases-part2.zip` تکرار کنید. در پایان باید **۷۱ تست** در لیست باشد.

> اگر Save تنظیمات score type بعد از آپلود تست‌ها خطای «No testcase matches» داد، یعنی تست‌ها کامل آپلود نشده‌اند.
> اسم تست‌ها باید مثل `0-01`، `1-01`، … و `5-19` باشد.

### ۳.۵ اضافه‌کردن سوال به آزمون
صفحه‌ی آزمون → **Tasks** → «Add a new task» → `lice` → **Add task**.

## مرحله ۴: شرکت‌کننده‌ها

1. منوی چپ → **Users** → کاربر جدید: نام، نام خانوادگی، Username، Password.
2. صفحه‌ی آزمون → **Users** → «Add a new user» → کاربر را انتخاب کنید → **Add user**.
3. برای خودتان هم یک کاربر تستی بسازید و در صفحه‌ی participation آن تیک **Hidden** را بزنید تا در رده‌بندی دیده نشود.

> ساخت تک‌تک کاربرها از پنل وقت‌گیر است. اگر تعداد زیاد است، فهرست را (CSV: نام، نام خانوادگی، نام کاربری، رمز)
> به مدیر سرور بدهید تا با `cmsAddUser` و `cmsAddParticipation` یکجا بسازد. دستورش در `docs/cms-guide-fa.md` بخش ۸ است.

---

## مرحله ۵: آزمایش (حتماً قبل از آزمون)

1. شروع آزمون را موقتاً به گذشته ببرید، یا آزمایش را بعد از شروع با کاربر hidden انجام دهید.
2. با کاربر تستی در صفحه‌ی شرکت‌کننده‌ها وارد شوید:
   - PDF متن باز می‌شود؟
   - `lice.zip` دانلود می‌شود؟
3. ارسال‌ها و نتیجه‌ی مورد انتظار (جدول کامل در `lice/README.md`):

   | فایل | امتیاز مورد انتظار |
   |---|---|
   | `solution/model.cpp` | **۱۰۰** |
   | `solution/slow_n2.cpp` | ۵۳ (TLE در زیرمسئله‌ی ۲ و ۵) |
   | `solution/brute.cpp` | ۱۰ |
   | `solution/wrong_le2.cpp` | ۰ |
   | `public/cpp/lice.cpp` (قالب خالی) | ۰، بدون خطای کامپایل |

   اگر با `model.cpp` همه Compilation failed شد، زبان آزمون یا managerها را چک کنید.
   اگر همه ۰ با پیام checker شد، فایل `checker` درست آپلود نشده یا Output evaluation روی comparator نیست.
4. **زمان‌ها**: در پنل ادمین، صفحه‌ی ارسال `model.cpp` زمان هر تست را نشان می‌دهد.
   - روی ماشین من بیشترین زمان 0.5 ثانیه بود.
   - اگر روی سرور بیشتر از حدود 0.8 ثانیه شد، یا `slow_n2.cpp` در زیرمسئله‌ی ۵ قبول شد، TL را بازبینی کنید:
     در dataset، **Clone** بزنید، در کپی TL را عوض کنید و آن را **Activate** کنید.
5. شروع آزمون را درست برگردانید.

## مرحله ۶: حین آزمون

- **Questions**: پرسش‌های شرکت‌کننده‌ها؛ از پنل جواب دهید.
- **Announcements**: اطلاعیه برای همه.
- **Submissions**: وضعیت داوری. اگر ارسال‌ها مدت زیادی در صف ماندند، به مدیر سرور خبر دهید (Worker یا سرویس‌ها).
- **وقت اضافه** برای یک نفر: صفحه‌ی participation آن کاربر در آزمون → Extra time.
- **داوری مجدد** بعد از اصلاح تست یا checker: در صفحه‌ی سوال یا dataset گزینه‌ی re-evaluate.
- خطاها و هشدارهای سیستم روی صفحه‌ی اول پنل ادمین نمایش داده می‌شوند.

## مرحله ۷: بعد از آزمون

- **Ranking** در صفحه‌ی آزمون: جدول نهایی را می‌توانید دانلود کنید.
- از مدیر سرور بخواهید نسخه‌ی پشتیبان بگیرد (`cmsDumpExporter`).
- برای هفته‌ی بعد:
  - آزمون جدید بسازید.
  - کاربرهای موجود را به آن اضافه کنید؛ کاربرها دوباره ساخته نمی‌شوند.
  - سوال‌های جدید را با همین روش بسازید.
  - ID آزمون جدید را برای ری‌استارت سرویس‌ها به مدیر سرور بدهید.
